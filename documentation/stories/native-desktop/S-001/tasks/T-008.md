# native-desktop/S-001-T8: OOM protection: max decode dimension 32768px in pixel_hash

**Status:** pending
**Priority:** P1
**Blocked By:** S-001-T7

## What
Enforce a maximum decode dimension in `crates/core::pixel_hash`. Images wider or taller than 32768px are skipped (not decoded to RGBA), and an error is recorded in file_cache.error instead. This prevents OOM crashes on panoramas and synthetic-dimension files.

## Why
CEO review CRITICAL GAP #1: 'OOM on huge images (100MP+ panoramas). The image crate decodes to full RGBA in memory. A 100MP image = ~400MB. No memory limit specified.' Without this guard, scanning a folder containing large panoramas or corrupted files with inflated dimension headers could crash the app with no user-visible error.

## Context
The pixel_hash module in T-007 already has a placeholder MAX_DECODE_DIMENSION constant at 32768. This task:
1. Makes the guard actually fire before decoding (check dimensions without full decode)
2. Adds a test fixture that claims huge dimensions (corrupt or synthetic header)
3. Integrates the error path with file_cache.error column (T-004 schema)

The image crate's ImageReader allows reading header dimensions before full decode:
```rust
let reader = ImageReader::open(path)?.with_guessed_format()?;
let (w, h) = reader.into_dimensions()?;
```
This reads only the header — no RGBA decode — so it's safe even on 100MP files.

## How

**Step 1 — Update pixel_hash::compute to pre-check dimensions:**
File: `crates/core/src/pixel_hash.rs`

Replace the current compute function body with:
```rust
pub fn compute(path: &Path) -> Result<[u8; 32]> {
    // Pre-check dimensions before full decode (avoids OOM on huge images)
    let reader = ImageReader::open(path)?.with_guessed_format()?;
    let (w, h) = reader.into_dimensions()
        .context('could not read image dimensions')?;

    if w > MAX_DECODE_DIMENSION || h > MAX_DECODE_DIMENSION {
        anyhow::bail!(
            'image dimensions {}x{} exceed max {}px — skipping pixel hash',
            w, h, MAX_DECODE_DIMENSION
        );
    }

    // Full decode only after dimension check passes
    let reader2 = ImageReader::open(path)?.with_guessed_format()?;
    let img = reader2.decode().context('decode failed')?;
    let rgba = img.to_rgba8();

    let mut hasher = Sha256::new();
    hasher.update(&rgba.width().to_be_bytes());
    hasher.update(&rgba.height().to_be_bytes());
    hasher.update(rgba.as_raw());
    Ok(hasher.finalize().into())
}
```

Note: into_dimensions() consumes the reader, so we re-open for the full decode. This is two file opens but avoids holding the reader while also tracking dimensions.

# Create a PNG with claimed dimensions > 32768 via header manipulation
# Use a tiny image with a spoofed header (PNG IHDR chunk)
import struct, zlib

def write_fake_huge_png(path, claimed_w, claimed_h):
    'Write a PNG with claimed huge dimensions but minimal data.'
    # PNG signature
    sig = b'\x89PNG
\x1a
'
    # IHDR chunk: width, height, bit_depth=8, color_type=2 (RGB), etc
    ihdr_data = struct.pack('>IIBBBBB', claimed_w, claimed_h, 8, 2, 0, 0, 0)
    ihdr_crc = zlib.crc32(b'IHDR' + ihdr_data) & 0xffffffff
    ihdr = struct.pack('>I', 13) + b'IHDR' + ihdr_data + struct.pack('>I', ihdr_crc)
    # Minimal IDAT (empty compressed data)
    idat_data = zlib.compress(b'')
    idat_crc = zlib.crc32(b'IDAT' + idat_data) & 0xffffffff
    idat = struct.pack('>I', len(idat_data)) + b'IDAT' + idat_data + struct.pack('>I', idat_crc)
    # IEND
    iend_crc = zlib.crc32(b'IEND') & 0xffffffff
    iend = struct.pack('>I', 0) + b'IEND' + struct.pack('>I', iend_crc)
    with open(path, 'wb') as f:
        f.write(sig + ihdr + idat + iend)

write_fake_huge_png(FIXTURE_DIR / 'huge_100000x100000.png', 100000, 100000)

fn huge_image_is_skipped_not_crashed() {

}
