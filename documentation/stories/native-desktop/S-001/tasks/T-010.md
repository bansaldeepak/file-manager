# native-desktop/S-001-T10: Schema migration failure dialog on Tauri startup

**Status:** pending
**Priority:** P1
**Blocked By:** S-001-T4

## What
In the Tauri app startup sequence (`crates/app`), catch any `IndexError::Migration` returned by `index::db::open` and show a blocking error dialog with the migration version that failed and a 'Reset cache' option. If the user chooses Reset, delete the SQLite file and retry opening.

## Why
CEO review CRITICAL GAP #3: 'Schema migration failure on app startup. No fallback specified.' Without this, a failed migration causes the app to simply not work — the user sees a crash, a blank window, or nothing at all. 'Reset cache' is safe because the cache contains only derived data (hashes), not source photos.

## Context
`index::db::open` (T-004) propagates IndexError::Migration when a migration fails. The app crate receives this at startup when initializing the database connection.

The 'Reset cache' action is SAFE: the SQLite file (`dedupe_cache.sqlite3`) is a derived cache — deleting it means the next scan re-hashes everything from scratch. No source photos are affected.

The dialog should be synchronous/blocking — the app must not proceed to the main window with a broken database.

Tauri 2 dialog API: `tauri::api::dialog::blocking::MessageDialogBuilder` for blocking dialogs.
```rust
use tauri::api::dialog::blocking::MessageDialogBuilder;
MessageDialogBuilder::new('Database Error', message)
    .buttons(MessageDialogButtons::OkCancelCustom('Reset Cache', 'Quit'))
    .show();
```

## How

**Step 1 — Create startup DB init function in app crate:**
File: `crates/app/src/startup.rs`
```rust
use std::path::PathBuf;
use dedupe_index::{db, IndexError};

pub fn init_database(db_path: &PathBuf) -> Result<rusqlite::Connection, String> {
    match db::open(db_path) {
        Ok(conn) => Ok(conn),
        Err(IndexError::Migration { version, source }) => {
            let message = format!(
                'Database migration to version {} failed:
{}

Choose Reset Cache to delete the scan cache and retry (your photos are not affected), or Quit to exit.',
                version, source
            );
            let choice = show_migration_error_dialog(&message);
            if choice == MigrationChoice::Reset {
                std::fs::remove_file(db_path).ok();
                db::open(db_path).map_err(|e| format!('Failed to reopen after reset: {e}'))
            } else {
                std::process::exit(1);
            }
        },
        Err(e) => Err(format!('Failed to open database: {e}')),
    }
}

#[derive(PartialEq)]
enum MigrationChoice { Reset, Quit }

fn show_migration_error_dialog(message: &str) -> MigrationChoice {
    use tauri::api::dialog::blocking::MessageDialogBuilder;
    use tauri::api::dialog::MessageDialogButtons;
    let confirmed = MessageDialogBuilder::new('Database Error', message)
        .buttons(MessageDialogButtons::OkCancelCustom('Reset Cache'.into(), 'Quit'.into()))
        .show();
    if confirmed { MigrationChoice::Reset } else { MigrationChoice::Quit }
}
```

**Step 2 — Call init_database from Tauri setup hook:**
File: `crates/app/src/main.rs` (or `lib.rs` if using the library pattern)
```rust
use std::sync::Mutex;

fn main() {
    let db_path = dirs::data_local_dir()
        .unwrap_or_else(|| std::path::PathBuf::from('.'))
        .join('Arcitae/dedupe_cache.sqlite3');

    std::fs::create_dir_all(db_path.parent().unwrap()).ok();

    let conn = startup::init_database(&db_path)
        .expect('database init failed after reset attempt');

    tauri::Builder::default()
        .manage(Mutex::new(conn))
        .run(tauri::generate_context!())
        .expect('Tauri error');
}
```
