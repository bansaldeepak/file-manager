# native-desktop/S-001-T12: Configurable I/O concurrency for external storage scanning

**Status:** pending
**Priority:** P3
**Blocked By:** S-001-T11

## What
Add a configurable concurrency limit for scanner I/O (directory walking + file reading), separate from the image decode semaphore (T-005). This lets the user reduce I/O parallelism when scanning slow external USB drives where saturating I/O makes things worse.

## Why
CEO review Section 7 WARNING: 'Need a configurable concurrency limit [for external storage], not hardcoded.' On a USB 3.0 drive, running 8 parallel file reads causes seeking/contention that's slower than sequential. A configurable rayon pool size lets the user tune this.

## Context
The scanner in T-011 uses `rayon::prelude::par_iter()` which automatically uses all available threads. This is fine for SSDs but harmful for mechanical or USB drives.

The decode semaphore (T-005) controls memory-intensive pixel hash decoding — that's separate from and cumulative with this I/O concurrency setting.

Implementation: expose a `scan_with_concurrency(root, concurrency: usize, progress)` variant that builds a custom rayon ThreadPool for the scan. Default (None) uses rayon global pool.

The concurrency setting can be stored in scan_metadata table (key='io_concurrency') and is user-configurable via the UI settings panel (a future story); for this task, just wire up the parameter and a test.

## How

**Step 1 — Update scanner::scan_directory to accept concurrency:**
File: `crates/core/src/scanner.rs` (modify function signature)
```rust
pub fn scan_directory(
    root: &Path,
    concurrency: Option<usize>,   // None = rayon default; Some(n) = n threads
    progress: impl Fn(usize) + Send + Sync,
) -> Result<Vec<ScannedFile>> {
    let entries: Vec<PathBuf> = collect_entries(root);
    info!('Scanning {} files with concurrency={:?}', entries.len(), concurrency);

    let results = if let Some(n) = concurrency {
        let pool = rayon::ThreadPoolBuilder::new()
            .num_threads(n)
            .build()?;
        pool.install(|| scan_entries_parallel(&entries, &progress))
    } else {
        scan_entries_parallel(&entries, &progress)
    };
    Ok(results)
}

fn collect_entries(root: &Path) -> Vec<PathBuf> {
    WalkDir::new(root)
        .follow_links(false)
        .into_iter()
        .filter_map(|e| e.ok())
        .filter(|e| e.file_type().is_file())
        .map(|e| e.path().to_path_buf())
        .collect()
}

fn scan_entries_parallel(
    entries: &[PathBuf],
    progress: &(impl Fn(usize) + Send + Sync),
) -> Vec<ScannedFile> {
    entries.par_iter().enumerate().map(|(i, path)| {
        progress(i);
        scan_file(path)
    }).collect()
}
```

```rust
#[test]
fn scan_with_concurrency_1_produces_same_results() {
    let fixtures = Path::new(concat!(env!('CARGO_MANIFEST_DIR'), '/../../tests/fixtures/images'));
    if !fixtures.exists() { return; }
    let default_files = scan_directory(fixtures, None, |_| {}).unwrap();
    let serial_files = scan_directory(fixtures, Some(1), |_| {}).unwrap();
    assert_eq!(default_files.len(), serial_files.len());
    // Both should find the same set of files (paths match after sort)
    let mut default_paths: Vec<_> = default_files.iter().map(|f| &f.path).collect();
    let mut serial_paths: Vec<_> = serial_files.iter().map(|f| &f.path).collect();
    default_paths.sort(); serial_paths.sort();
    assert_eq!(default_paths, serial_paths);
}
```
