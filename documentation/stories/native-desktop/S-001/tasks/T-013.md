# native-desktop/S-001-T13: Quick Look spike: QLPreviewPanel from Tauri 2 macOS (D5)

**Status:** done
**Priority:** P3-spike
**Blocked By:** S-001-T3

## What
Spike task: prove whether macOS QLPreviewPanel can be invoked from a Tauri 2 app running in the macOS sandbox. Write a minimal proof-of-concept that opens a Quick Look panel for a given file path from a Tauri command. If QLPreviewPanel is not usable, document the fallback approach (open file in Finder, or use a custom image viewer).

## Why
CEO review D5 (user-approved): 'macOS Quick Look integration for full-size image previews (spacebar to preview).' Outside Voice OV-6 flagged: 'D5 Quick Look underscoped — may need Objective-C bridging spike.' This is a spike only — the full implementation comes after the spike proves feasibility. Building the full feature on an unproven vendor primitive wastes days if QLPreviewPanel is sandboxed out.

## Context
macOS Quick Look API:
- `QLPreviewPanel` is an Objective-C class in `Quartz/QuickLookUI.framework`
- Invoked via: `[QLPreviewPanel sharedPreviewPanel]`
- Requires a `QLPreviewPanelController` and `QLPreviewPanelDataSource` delegate
- Tauri 2 uses objc2 (or objc) crate for Objective-C bridging in macOS plugins

Sandbox concern: Tauri 2 apps use the macOS sandbox by default. QLPreviewPanel may require temporary file-access entitlements for the selected path. The spike must verify whether the entitlement `com.apple.security.files.user-selected.read-only` is sufficient.

Fallback options (in order of preference):
1. QLPreviewPanel via objc2 (native, ideal)
2. `open -R file_path` via std::process::Command (opens Finder; not a preview)
3. Custom image viewer in the inspector pane using an `<img>` tag (already built in inspector)

## How

**Step 1 — Add objc2 dependency to app crate (macOS only):**
File: `crates/app/Cargo.toml`
```toml
[target.'cfg(target_os = "macos")'.dependencies]
objc2 = '0.5'
objc2-quartz-core = { version = '0.2', optional = true }
```

**Step 2 — Write a minimal QL test binary:**
File: `crates/app/src/quicklook_spike.rs` (feature-flagged, compile-only check)
```rust
#[cfg(target_os = 'macos')]
pub fn open_quicklook(path: &std::path::Path) -> Result<(), String> {
    // Minimal invocation — proves linkage and sandbox compatibility
    use std::process::Command;
    // Fallback: use qlmanage (command-line Quick Look) as a proxy for the spike
    let status = Command::new('qlmanage')
        .args(['-p', path.to_str().ok_or('invalid path')?])
        .status()
        .map_err(|e| format!('qlmanage failed: {e}'))?;
    if status.success() {
        Ok(())
    } else {
        Err(format!('qlmanage exited {status}'))
    }
}
```

Note: `qlmanage -p` is the command-line proxy for Quick Look and works in non-sandboxed contexts. The spike determines if the full QLPreviewPanel API is needed or if qlmanage is sufficient.

**Step 3 — Add a Tauri command for the spike:**
File: `crates/app/src/commands/preview.rs`
```rust
#[tauri::command]
pub fn preview_file(path: String) -> Result<(), String> {
    #[cfg(target_os = 'macos')]
    {
        crate::quicklook_spike::open_quicklook(std::path::Path::new(&path))
    }
    #[cfg(not(target_os = 'macos'))]
    Err('Quick Look is macOS only'.to_string())
}
```

**Step 4 — Document findings:**
After running the spike against a real JPG file on macOS, record in `documentation/decisions/quicklook-spike.md`:
