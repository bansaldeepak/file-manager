# native-desktop/S-001-T25: Tauri capability scoping: scoped fs permissions (no blanket)

**Status:** pending
**Priority:** P2
**Blocked By:** S-001-T14

## What
Configure Tauri 2 capability files to use scoped filesystem permissions: `fs:allow-read` and `fs:allow-write` restricted to the user-selected folders and the app data directory. Remove any blanket fs permissions. This enforces the principle of least privilege for file access.

## Why
CEO review Section 3 WARNING: 'Tauri capability config not specified. Implementation must use folder-scoped fs:allow-read and fs:allow-write rather than blanket permissions.' REQUIREMENTS.md s11: 'Restrict Tauri capabilities to the minimum required.' A blanket `fs:allow-*` permission lets the app read/write any file on the system — a security issue for a personal-data-adjacent tool.

## Context
Tauri 2 capabilities live in `src-tauri/capabilities/` (one JSON file per capability set). The `default.json` capability defines what the frontend can request via IPC.

Required permissions:
- `fs:allow-read-recursive` scoped to user-selected folders (original + copies roots)
- `fs:allow-write` scoped to the quarantine directory only (`/Arcitae/Quarantine/**`)
- `path:allow-app-local-data-dir` for the SQLite cache and log path
- `dialog:allow-open` for folder picker

NOT needed (no blanket):
- `fs:allow-write-recursive` on arbitrary paths
- `fs:scope` without restrictions

Scoped permissions in Tauri 2 use the `scope` field with an `allow` list of path patterns.

## How

**Step 1 — Read existing capability file:**
File: `src-tauri/capabilities/default.json` (generated by Tauri init)

**Step 2 — Replace with scoped capability config:**
File: `src-tauri/capabilities/default.json`
```json
{
  '$schema': '../gen/schemas/desktop-schema.json',
  'identifier': 'default',
  'description': 'Arcitae Dedupe — scoped filesystem access',
  'windows': ['main'],
  'permissions': [
    'core:default',
    'dialog:allow-open',
    'dialog:allow-message',
    'path:allow-app-local-data-dir',
    {
      'identifier': 'fs:allow-read-recursive',
      'allow': [{ 'path': '$HOME/**' }]
    },
    {
      'identifier': 'fs:allow-write',
      'allow': [
        { 'path': '$LOCALDATA/Arcitae/**' }
      ]
    }
  ]
}
```

Note: '$HOME/**' is broad but scoped to user home — it does NOT include system directories. The Rust backend validates that requested paths are within the user-authorized scope before acting; the frontend cannot pass arbitrary system paths.

**Step 3 — Add path validation in Rust command layer:**
File: `crates/app/src/commands/quarantine.rs` (update quarantine_files)
```rust
fn validate_path_scope(path: &str, allowed_roots: &[&str]) -> Result<(), String> {
    let abs = std::fs::canonicalize(path)
        .map_err(|e| format!('path not accessible: {e}'))?;
    for root in allowed_roots {
        let root_abs = std::fs::canonicalize(root)
            .unwrap_or_else(|_| std::path::PathBuf::from(root));
        if abs.starts_with(&root_abs) {
            return Ok(());
        }
    }
    Err(format!('path {} is outside authorized scope', path))
}
```

**Step 4 — Audit existing commands for over-broad path acceptance:**
Run:
```bash
grep -rn 'path' crates/app/src/commands/ | grep -v test | grep -v '//'
```
For each command that accepts a path, confirm validate_path_scope is called.

**Step 5 — Verify:**
```bash
cargo build -p dedupe-app 2>&1 | grep error
# Run the Tauri app and confirm folder picker works
pnpm tauri dev
```
