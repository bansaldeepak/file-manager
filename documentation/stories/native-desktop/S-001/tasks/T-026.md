# native-desktop/S-001-T26: cargo audit in pre-release script

**Status:** done
**Priority:** P2
**Blocked By:** —

## What
Add `cargo audit` to a pre-release check script (or CI hook) that runs before any release build. It should exit non-zero if any known vulnerabilities are found in the dependency tree. Document the check and its threshold in the release process.

## Why
CEO review Section 3 WARNING: 'No cargo audit in CI specified. Dependency vulnerability scanning is missing from Stage 6 exit evidence.' REQUIREMENTS.md s4.2: 'Review each dependency's license, maintenance status, security posture.' For a tool that handles personal photo files and performs filesystem operations, supply chain hygiene matters.

## Context
`cargo audit` reads `Cargo.lock` and checks against the RustSec advisory database. It must be installed separately: `cargo install cargo-audit`.

For a personal local tool, the bar is: no known exploitable vulnerabilities in the direct dependency path to filesystem operations (rusqlite, image crate, tauri). Advisories that only affect network servers can be accepted with a documented rationale.

This task creates a shell script at `scripts/pre-release-check.sh` that packages all pre-release checks.

## How

**Step 1 — Install cargo-audit:**
```bash
cargo install cargo-audit
```

**Step 2 — Create pre-release check script:**
File: `scripts/pre-release-check.sh`
```bash
#!/usr/bin/env bash
set -euo pipefail

echo '=== Pre-release checks ==='

echo '1. Cargo build --workspace'
cargo build --workspace --release

echo '2. Cargo test --workspace'
cargo test --workspace

echo '3. Cargo audit'
cargo audit --deny warnings

echo '4. Python app still works'
source .venv/bin/activate
python -m py_compile app.py

echo '=== All checks passed ==='
```

Make executable:
```bash
chmod +x scripts/pre-release-check.sh
```

**Step 3 — Add audit configuration:**
File: `audit.toml` (project root)
```toml
[advisories]
# Accept informational advisories; deny warnings and above
ignore = []

[output]
quiet = false
```

**Step 4 — Run the audit and record baseline:**
```bash
cargo audit 2>&1
```
If any advisories are found, document them in `documentation/decisions/cargo-audit-baseline.md` with:
- Advisory ID
- Affected crate and version
- Severity
- Rationale for accept/fix
- Tracking: upgrade when a fixed version is available

**Step 5 — Add pre-commit hook (optional, requires manual setup):**
File: `.git/hooks/pre-push` (document, not auto-installed)
```bash
#!/usr/bin/env bash
echo 'Running cargo audit before push...'
cargo audit --deny warnings || exit 1
```

**Step 6 — Verify:**
```bash
bash scripts/pre-release-check.sh 2>&1 | tail -20
```
