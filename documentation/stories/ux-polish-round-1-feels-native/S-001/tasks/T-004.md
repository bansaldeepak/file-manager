# ux-polish-round-1-feels-native/S-001-T4: Left-truncated filenames

**Status:** pending
**Priority:** P1
**Blocked By:** —

## Description

DESIGN.md spec: "Filename left-truncated (filename always readable at right)." Currently filenames use standard right-truncation (text-overflow: ellipsis) which hides the actual filename and shows the beginning of the path.

Use the CSS direction trick: `direction: rtl; text-align: left;` — this makes text-overflow: ellipsis truncate from the left while keeping the text visually left-aligned.

## Files to modify

### `frontend/src/components/ContactSheet.css`

- `.keeper-card-name` (line 292): add `direction: rtl; text-align: left;`

### `frontend/src/components/QuarantineView.css`

- `.qv-card-name` (line 339): add `direction: rtl; text-align: left;`

### `frontend/src/components/DuplicateInspector.css`

- `.di-copy-label` (line 296): add `direction: rtl; text-align: left;` (change existing `text-align: center` to `text-align: left`)

## Important

Do NOT apply left-truncation to path breadcrumbs — only to standalone filename display elements. Breadcrumbs already handle truncation by showing the last 3 segments.

## Verify

Build and run with images that have long filenames (e.g., "IMG_20230415_143256_HDR_portrait_enhanced.jpg"). The filename portion should be visible at the right of the truncation, with ellipsis at the left if it overflows.
