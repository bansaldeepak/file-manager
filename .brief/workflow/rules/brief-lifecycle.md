# Brief Lifecycle Controls

For brief work read the installed router and phase; the router owns lifecycle order. Honor explicit
user instructions and approval at stated scope. Reconcile conflicting legacy brief boilerplate;
do not silently override a custom project restriction.

- PRD/TRD/tasks explicitly consume applicable rules, agent guidance, decisions, and user preferences.
  Apply them in design and actionable tasks; implementation still checks current rules.
- Investigate uncertainty; ask if intended behavior/scope remains unclear. Block dependent work in
  all modes. Do not guess, repeat settled questions, or treat timeouts as consent.
- User selects strict/selective/auto per story after a risk-based recommendation. No silent switches,
  cross-story consent, or assumption that auto authorizes migration execution/deploy/publication.
- Review and fix all introduced/worsened issues before push/PR regardless of severity. Existing debt
  is the user's choice. Review/fix precedes final verification.
- Retro/curation completes authorized memory/rule/skill/agent improvements before publication by
  default. Explicit urgency can defer with owner/trigger; later changes need review and checks.
  A clean user test requires no repeat retro before user merge.
- Capture explicit choices immediately with source and stated scope in the repo knowledge store.
  Ask before broader promotion. Code contradicting a preference does not invalidate the preference.
